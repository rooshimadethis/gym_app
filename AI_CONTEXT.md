# Gym app development context

- Flutter app with Drift persistence. XP rules live in `lib/domain/gamification.dart`; awards are persisted through `GamificationService`. UI changes must preserve award deduplication and abandoned-attempt exclusion from performance history.
- Motivation centers on starting a workout and recognizing effort. Preserve automatic focus/keyboard opening for the next set.
- Run `flutter run -d <device> -t lib/ui_preview.dart` for a database-free gallery of production check-in, effort editor, XP feedback, and receipt widgets. The keyboard preview reproduces feedback while the numeric keyboard is open. Default builds use `lib/main.dart`.
- Feedback overlay entries need Material styling and live keyboard insets. Verify screenshots and input focus as well as analyzer/tests; widget tests alone do not establish visual quality.
- XP reward cards animate persisted before/after lifetime XP through the level bar, including rollover. Consecutive set/exercise awards combine into one card. Keep reduced-motion support, automatic next-set focus, and the 3-second workout-start celebration intact.
- Reward cards last 5 seconds with a quick fill and readable hold. Overlay controllers preserve duration explicitly because Flutter otherwise shortens them when Android animations are disabled; reduced-motion visuals are handled separately.
- For Android installs on a personal phone use `adb install -r` to preserve data. Do not uninstall the app for iteration. Emulator builds of the preview entry point are development tools, not the APK to install on the phone.
- Set corrections go through `GamificationService.editHistorySet` (updates history + linked set, never XP). Undo is current-workout-only and transactionally revokes set/completion XP before reopening the attempt. Logged-set menus and the 8-second completion snackbar expose these actions; undo restores exercise/group list position.
- `BackupService` exports version 1 snapshots of all five Drift tables, exercise JSON, and the settings allowlist. Parse/validate before confirmation; replace in a SQLite transaction with compensating preferences rollback. Legacy imports detach missing attempt refs and reset XP with an explicit warning. Restore is blocked during workouts and never resumes backed-up active attempts. SQLite and preferences are separate stores, so compensation covers handled errors, not process termination mid-restore.
- Exercise progress/history uses unbounded completed/legacy history by stable exercise ID. Warmups and zero-rep sets do not influence best sets; compare reps only at the same load. `lib/ui_preview.dart` includes an in-memory history/correction preview; it never opens personal data.
- Older abandoned attempts may point to removed history. Export detaches only missing history links on abandoned attempts in the snapshot, preserving set/XP records and leaving storage untouched. Import validation remains strict. Optional read-only local-data regression uses `flutter test --no-pub --reporter failures-only --dart-define=BACKUP_DIAGNOSTIC_DB=<approved-copy-path>`; personal diagnostic artifacts must never be committed.
- Validation: `flutter analyze --no-fatal-infos`, `flutter test --no-pub -r compact`. Flutter currently auto-adds migration flags to `android/gradle.properties` during Android builds; keep unrelated generated migration changes out of UI work.

- Warmup classification is now `Exercise.warmupSetEnabled`, persisted per exercise. Old JSON and backups inherit `warmup_set_enabled` once; explicit flags win. New exercises default off. The toolbar warmup shortcut reveals the detail switch after automatic set scrolling. The switch marks the existing first set as a warmup (does not add/remove sets) and locks once an attempt starts to preserve logged classification. `saveExerciseWarmup` saves only that flag by stable ID immediately.
- Volume = sum of weight × reps across non-warmup completed-session sets. Detail/history share a line graph in `ExerciseVolumeChart` for the last six sessions, ordered oldest to newest with session spacing and a zero-based volume scale; fetch all history before grouping so long sessions are not truncated. History corrections refresh totals. Zero-load exercises show zero external-load volume. Preview gallery includes the warmup/volume controls with synthetic history.
